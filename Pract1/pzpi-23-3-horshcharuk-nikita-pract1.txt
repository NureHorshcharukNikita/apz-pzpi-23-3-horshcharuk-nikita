3.1 Загальні відомості про шаблони проєктування
     Шаблони (патерни) проєктування програмного забезпечення являють собою типові, багаторазово перевірені рішення поширених проблем, які виникають під час розроблення програмних систем. Вони не є готовими фрагментами програмного коду, а визначають загальні принципи побудови структури програм та взаємодії їх компонентів.
     У праці «Design Patterns: Elements of Reusable Object-Oriented Software» (GoF) шаблони проєктування поділяються на три основні групи:
* породжувальні;
* структурні;
* поведінкові.
     Поведінкові шаблони визначають способи взаємодії між об’єктами та розподіл відповідальності між ними. Одним із таких шаблонів є Strategy, який дозволяє змінювати алгоритми під час виконання програми.
3.2 Опис обраного патерна
     Назва патерна: Strategy
     Тип шаблона: поведінковий
     Основне призначення шаблона Strategy полягає у визначенні сімейства алгоритмів, інкапсуляції кожного з них в окремому класі та забезпеченні можливості їх взаємозамінного використання.
     Застосування даного шаблона доцільне у випадках, коли:
* існує декілька варіантів виконання однієї операції;
* необхідно змінювати поведінку програми під час виконання;
* потрібно уникнути великої кількості умовних операторів;
* є потреба у розширенні функціональності без зміни існуючого коду.
     Переваги шаблона:
* підвищення гнучкості програмної системи;
* спрощення розширення функціональності;
* зменшення зв’язності між компонентами;
* відповідність принципу відкритості/закритості.
     Недоліки:
* збільшення кількості класів;
* ускладнення структури програми;
* необхідність додаткового проєктування.
3.3 Структура шаблона (патерна)
     До складу шаблона Strategy входять такі основні елементи:
* Strategy (інтерфейс) – визначає загальний метод виконання алгоритму.
* ConcreteStrategy – реалізує конкретний алгоритм.
* Context – використовує об’єкт стратегії та делегує йому виконання операції.
     Взаємодія об’єктів полягає в тому, що клієнт передає об’єкт стратегії до контексту, після чого контекст викликає відповідний метод, не знаючи деталей реалізації алгоритму. Такий підхід дозволяє змінювати алгоритм без зміни коду контексту.
     Для наочного представлення структури шаблона Strategy використовується UML-діаграма класів, наведена на рисунку 3.1.

Рисунок 3.1 - UML-діаграма класів шаблона Strategy

     На діаграмі показано інтерфейс Strategy, який визначає загальний метод алгоритму. Класи ConcreteStrategyA, ConcreteStrategyB та ConcreteStrategyC реалізують цей інтерфейс та містять конкретні алгоритми. Клас Context містить посилання на об’єкт типу Strategy та делегує йому виконання операції.

3.4.1 Приклад 1 — Арифметичні операції
     У першому прикладі шаблон Strategy використовується для вибору арифметичної операції.
     Було реалізовано:
* інтерфейс IStrategy;
* класи стратегій для додавання, віднімання та множення;
* клас Context, який делегує виконання обраній стратегії.
     Кожна операція реалізується окремим класом, що дозволяє легко додавати нові алгоритми без зміни існуючого коду.
     Нижче наведено реалізацію інтерфейсу стратегії:
      1  public interface IStrategy
      2  {
      3      int Execute(int a, int b);
      4  }
     
     Даний інтерфейс визначає єдиний метод для виконання операцій.
     Реалізація конкретних стратегій:
      5  public class AdditionStrategy : IStrategy
      6  {
      7      public int Execute(int a, int b)
      8      {
      9          return a + b;
      10     }
      11 }
      12 
      13 public class SubtractionStrategy : IStrategy
      14 {
      15     public int Execute(int a, int b)
      16     {
      17         return a - b;
      18     }
      19 }
      20 
      21 public class MultiplicationStrategy : IStrategy
      22 {
      23     public int Execute(int a, int b)
      24     {
      25         return a * b;
      26     }
      27 }
     
     Кожен клас відповідає за окремий алгоритм, що дозволяє ізолювати логіку та спростити підтримку коду.
     Клас контексту:
      28 public class Context
      29 {
      30     private IStrategy _strategy;
      31 
      32     public Context(IStrategy strategy)
      33     {
      34         _strategy = strategy;
      35     }
      36 
      37     public void SetStrategy(IStrategy strategy)
      38     {
      39         _strategy = strategy;
      40     }
      41 
      42     public int ExecuteStrategy(int a, int b)
      43     {
      44         return _strategy.Execute(a, b);
      45     }
      46 }
     
     Клас Context не реалізує алгоритм самостійно, а делегує його виконання об’єкту стратегії.
     Приклад використання:
      47 Context context = new Context(new AdditionStrategy());
      48 Console.WriteLine(context.ExecuteStrategy(10, 5));
      49 
      50 context.SetStrategy(new SubtractionStrategy());
      51 Console.WriteLine(context.ExecuteStrategy(10, 5));
     
     У даному прикладі видно, що зміна стратегії дозволяє змінити результат виконання без зміни структури програми..
3.4.2 Приклад 2 — Поведінка персонажа у грі
     У другому прикладі шаблон Strategy застосовано для моделювання поведінки персонажа у комп’ютерній грі.
     Персонаж може використовувати різні типи атаки:
* атака мечем;
* атака луком;
* магічна атака.
     Кожен тип атаки реалізовано як окрему стратегію. Клас персонажа містить посилання на поточну стратегію та виконує її під час атаки.
     Інтерфейс стратегії:
      1  public interface IAttackStrategy
      2  {
      3      void Attack();
      4  }
     
     Реалізація стратегій:
      5  public class SwordAttack : IAttackStrategy
      6  {
      7      public void Attack()
      8      {
      9          Console.WriteLine("Персонаж атакує мечем");
      10     }
      11 }
      12 
      13 public class BowAttack : IAttackStrategy
      14 {
      15     public void Attack()
      16     {
      17         Console.WriteLine("Персонаж стріляє з лука");
      18     }
      19 }
      20 
      21 public class MagicAttack : IAttackStrategy
      22 {
      23     public void Attack()
      24     {
      25         Console.WriteLine("Персонаж використовує магію");
      26     }
      27 }
     
     Клас персонажа:
      28 public class Character
      29 {
      30     private IAttackStrategy _attackStrategy;
      31 
      32     public void SetAttackStrategy(IAttackStrategy strategy)
      33     {
      34         _attackStrategy = strategy;
      35     }
      36 
      37     public void PerformAttack()
      38     {
      39         _attackStrategy.Attack();
      40     }
      41 }
     
     Приклад використання:
      42 Character hero = new Character();
      43 
      44 hero.SetAttackStrategy(new SwordAttack());
      45 hero.PerformAttack();
      46 
      47 hero.SetAttackStrategy(new MagicAttack());
      48 hero.PerformAttack();
     
     Такий підхід дозволяє змінювати поведінку персонажа під час виконання програми без зміни його класу. Це є ключовою перевагою шаблона Strategy та демонструє його ефективність у задачах, де поведінка може змінюватися динамічно.

* Проаналізовано принцип роботи шаблона Strategy, який полягає в інкапсуляції алгоритмів у окремі класи та забезпеченні можливості їх взаємозамінного використання без зміни основного коду програми.
* Реалізовано два приклади застосування шаблона мовою програмування C#: для виконання арифметичних операцій та для моделювання поведінки персонажа у комп’ютерній грі.
* Продемонстровано, що використання шаблона Strategy дозволяє підвищити гнучкість програмного забезпечення, спростити його розширення та зменшити залежність між компонентами системи.
* Отримано практичні навички застосування шаблонів проєктування при розробленні програмного забезпечення, що сприяє створенню більш структурованого, зрозумілого та підтримуваного коду.

5      public interface IStrategy
6      {
7          int Execute(int a, int b);
8      }
9  
10     public class AdditionStrategy : IStrategy
11     {
12         public int Execute(int a, int b)
13         {
14             return a + b;
15         }
16     }
17 
18     public class SubtractionStrategy : IStrategy
19     {
20         public int Execute(int a, int b)
21         {
22             return a - b;
23         }
24     }
25 
26     public class MultiplicationStrategy : IStrategy
27     {
28         public int Execute(int a, int b)
29         {
30             return a * b;
31         }
32     }
33 
34     public class Context
35     {
36         private IStrategy _strategy;
37 
38         public Context(IStrategy strategy)
39         {
40             _strategy = strategy;
41         }
42 
43         public void SetStrategy(IStrategy strategy)
44         {
45             _strategy = strategy;
46         }
47 
48         public int ExecuteStrategy(int a, int b)
49         {
50             return _strategy.Execute(a, b);
51         }
52     }
53 
54     internal class Program
55     {
56         static void Main(string[] args)
57         {
58             Context context = new Context(new AdditionStrategy());
59             Console.WriteLine("Додавання: " + context.ExecuteStrategy(10, 5));
60

62             Console.WriteLine("Віднімання: " + context.ExecuteStrategy(10, 5));
63 
64             context.SetStrategy(new MultiplicationStrategy());

66         }
